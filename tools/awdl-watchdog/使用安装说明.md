# Awdl Watch Dog· 安装与使用说明

一个 60 秒自检一次的 launchd 守护进程，自动修复 **睡眠唤醒后隔空投送 / 接力失效** 的问题。

---

## 一、先确认你要不要装

### 如果你遇到如下问题就需要安装：

- 长时间睡眠唤醒/长时间运行系统隔空投送**找不到任何设备**
- 接力，通用剪贴板失效（iPhone 上复制的文字，Mac 上粘贴不出来）
- 这些症状**重启之后就正常**，但用几小时又会犯
- Wi-Fi 本身完全正常，网页能上、下载正常

> **它和 kext 完全独立。** 不装它，kext 该有的功能一个不少；装了它，也不会改变 kext 的任何行为。

---

## 二、安装教程

### 前置条件

| 项目 | 要求                                          |
| ---- | --------------------------------------------- |
| 系统 | macOS，管理员账号                             |
| 依赖 | 无。纯 shell + 系统自带 `ioreg` / `launchctl` |
| 磁盘 | 约 8 KB                                       |

### 操作

在Releases里下载Awdl Watch Dog.zip

解压缩

右键解压缩出来的文件夹-服务-新建位于文件夹位置的终端窗口

```bash
sudo sh "install.sh"
```

需要输入一次管理员密码。成功时会打印类似内容：

```
已安装并启动。当前状态：
state = running
program = /bin/sh
runs = 1
last exit code = (never exited)
日志：/var/log/awdl-watchdog.log
```

### 它装了什么

| 文件                                                   | 作用                           |
| ------------------------------------------------------ | ------------------------------ |
| `/usr/local/bin/awdl-watchdog.sh`                      | 主脚本（201 行）               |
| `/Library/LaunchDaemons/com.local.awdl-watchdog.plist` | launchd 配置，60 秒一轮        |
| `/var/tmp/awdl-watchdog.state`                         | 状态文件（8 个字段），自动生成 |
| `/var/log/awdl-watchdog.log`                           | 日志                           |

除此之外**不碰系统任何文件**，不改 SIP，不改 NVRAM，不装内核扩展。

## 三、装完怎么确认它是好的

### 1. 服务在跑

```bash
launchctl print system/com.local.awdl-watchdog | grep -E "state|runs|last exit"
```

- `state = not running` —— **正常**。它每次只运行零点几秒就退出，两次之间就是这个状态
- `runs` —— 每 60 秒 +1，说明在正常轮询
- `last exit code = 0` —— 上次退出正常

### 4. 日志

```bash
tail -20 /var/log/awdl-watchdog.log
```

**正常情况下它几乎不写日志。** 只有三种内容会出现：

| 内容                                  | 含义                              |
| ------------------------------------- | --------------------------------- |
| `baseline: peers N, live M`           | 安装 / 开机后第一次记录起点。正常 |
| `woke after a Ns gap, ...`            | 检测到机器睡过觉，开始观察        |
| `restarting sharingd/wifip2pd -- ...` | **它动手了**                      |

日志长期为空是**正确状态**，不是坏了。

## 四、日常怎么用

**什么都不用做。** 它自己判断、自己修、自己记日志。

想看它最近干过什么：

```bash
tail -20 /var/log/awdl-watchdog.log
```

想知道它现在的判断依据：

```bash
cat /var/tmp/awdl-watchdog.state
```

8 个字段依次是：

| 位置 | 含义                                   |
| ---- | -------------------------------------- |
| 1    | 上次的接收计数（sync + data）          |
| 2    | 计数最后一次变化的时间戳               |
| 3    | 上次动作的时间戳                       |
| 4    | 本轮已尝试次数                         |
| 5    | 本轮的唤醒是否已处理                   |
| 6    | 醒来时间戳                             |
| 7    | **本会话是否听到过对端**（1 = 听到过） |
| 8    | 上次运行时间戳                         |

第 7 个字段是理解它行为的关键：**手机整天不在旁边时它是 0，看门狗一次都不会动手。**

## 六、卸载

```bash
sudo sh tools/awdl-watchdog/uninstall.sh
```

完全移除：注销 launchd 作业、删除 plist、删除脚本、删除状态文件。

**日志会保留**，需要的话单独删：

```bash
sudo rm -f /var/log/awdl-watchdog.log
```

卸载后系统回到原样，隔空投送照常工作，只是再出问题时需要手动处理。

## 七、常见问题

### 会不会把 AirPods 弄断？

不会。它**故意不杀 `bluetoothd`**——三个服务里只有它重启会被你察觉（音频瞬断），而持有过期频道的是另外两个。

### 会不会耗电？

每 60 秒执行一次 `ioreg` 查询，耗时几十毫秒。另外有一条硬规则：**你离开电脑超过 5 分钟，它就不动作**，所以整夜不会反复重启。

### 手机放另一个房间，会不会被误判成故障？

不会主动误判。判定要求「**本会话曾经收到过对端帧**」，手机整天不在旁边时这个条件永远不成立。

唯一的残留情况：手机陪你几小时（收到过帧），然后你把它拿走两小时。这时它可能误判并动作，最多 3 次、每次间隔 ≥ 30 分钟，然后停手。因为不杀蓝牙，实际基本无感。

### 它动作了，但问题没解决？

说明病因不是这个。先看日志里记录的动作瞬间计数：

- `peers` 为 0 → 手机确实不在旁边，属正常，不是故障
- `peers` ≥ 1 但重启无效 → 可能需要连 `bluetoothd` 一起重启，把日志发出来

### 安装时报 `Bootstrap failed: 5: Input/output error`？

launchd 还占着旧作业。先卸载再装：

```bash
sudo sh tools/awdl-watchdog/uninstall.sh
sudo sh tools/awdl-watchdog/install.sh
```

### 我怎么确认它真的会动手，而不是永远静默？

用演练模式，**不会真的重启任何东西**：

```bash
AWDL_WATCHDOG_DRY_RUN=1 AWDL_WATCHDOG_STATE=/tmp/w.state \
AWDL_LOG=/tmp/w.log sudo sh /usr/local/bin/awdl-watchdog.sh
```

把状态文件里的唤醒时间改成 90 秒前、对端表有记录，再跑一次，就会打印 `would restart: ...`。详见 [README.md](README.md) 的「手动验证」一节。
